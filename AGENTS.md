# Agent instructions

Monitor Control is a Windows tray app that sets an external monitor's brightness, contrast and input over DDC/CI. It talks to the monitor through `dxva2.dll`, uses WPF for the panel and WinForms `NotifyIcon` for the tray. It runs only on Windows.

## Build

```
build.cmd
```

- Uses the .NET Framework 4.8 `csc.exe` from `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319`. No .NET SDK, NuGet or Visual Studio is needed or used. Don't add a `.csproj` or switch to `dotnet build`.
- That compiler only accepts **C# 5**: no string interpolation (`$"..."`), no `?.`, no `nameof`, no expression-bodied members, no tuples, no `out var`. Match the existing code.
- Output: `dist\Monitor Control\` (exe, launcher, `app\` sources, README, license) and `dist\MonitorControl-<version>-portable.zip`. `dist\` is wiped on each build and git-ignored.
- `assets\app.ico` is generated by `tools\make-icon.ps1` if it is missing.
- The version lives in three places: `build.cmd` (`VERSION`), `src\AssemblyInfo.cs` and `Program.Version`. Keep them in sync.

## Run

There are two ways to start the app, and both use the same code:

1. **Exe:** `dist\Monitor Control\Monitor Control.exe`. It is unsigned, so **Smart App Control blocks it** on PCs where SAC is on ("An Application Control policy has blocked this file"). You can check SAC with `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy\VerifiedAndReputablePolicyState` (1 = on).
2. **PowerShell launcher:** `dist\Monitor Control\Monitor Control.ps1`. It compiles `app\*.cs` in memory with `Add-Type` and calls `MonitorControl.Program.Main`. SAC allows this. Use it whenever the exe is blocked:
   ```
   conhost.exe --headless powershell.exe -NoProfile -WindowStyle Hidden -File "dist\Monitor Control\Monitor Control.ps1"
   ```
   - Don't add `-ExecutionPolicy Bypass`. It isn't needed for local scripts under RemoteSigned, and agent safety checks reject it.
   - `--tray` (exe) or `-Tray` (script) starts hidden in the tray.

You can also skip the build and run straight from source by mirroring what the launcher does: `Add-Type -Path src\*.cs` with the referenced assemblies listed in `package\Monitor Control.ps1`, plus `-IgnoreWarnings`. Then set `[MonitorControl.Program]::BaseDirectory = 'src'` so `MainWindow.xaml` is found, and copy `assets\app.ico` into `src\` (or point `BaseDirectory` at a folder that has both files).

## Verify it works

- Check that the process starts and stays running. Windows PowerShell can only `Add-Type` a type name once per session, so launch each test in a **new** process.
- Errors go to `%LOCALAPPDATA%\MonitorControl\error.log`. The launcher also shows a message box if compiling fails. Check the log after every launch.
- **Single instance:** the app uses the mutex `Local\MonitorControl.App.SingleInstance` and the event `Local\MonitorControl.App.Show`. If a copy is already running, a new launch only tells that copy to open its panel and then exits with code 0, so it looks like "nothing happened". Stop the old process first: `Get-CimInstance Win32_Process` and filter on a command line that contains `Monitor Control`.
- A screenshot of the work area (bottom-right corner, above the tray) shows the panel with live values. The monitor name, brightness, contrast and highlighted input should match the monitor's own OSD.
- DDC/CI needs a real monitor with DDC/CI turned on in its OSD. Remote Desktop sessions, VMs, laptop panels and some docks/adapters don't support it, so reads fail there. That is an environment limit, not a bug.

## Code map

| File | Role |
| --- | --- |
| `src\Program.cs` | Entry point, single instance, Run-key "Open at Login" (`LoginItem`), tray icon and menu (`TrayApp`), resource loading, error log |
| `src\PanelWindow.cs` | The popover panel: sliders, presets, input segmented control, polling, writes on a background thread |
| `src\MainWindow.xaml` | Panel layout and styles. Loaded at runtime with `XamlReader` (no code-behind or BAML), so named elements are looked up with `FindName` |
| `src\DdcMonitor.cs` | Monitor enumeration, friendly names via WMI, VCP get/set with retries. VCP codes: `0x10` brightness, `0x12` contrast, `0x60` input |
| `src\PillSlider.cs` | Custom-drawn Control Center-style slider |
| `src\Theme.cs` | Light/dark brushes, following `AppsUseLightTheme` |
| `src\Native.cs` | P/Invoke declarations |
| `package\Monitor Control.ps1` | The in-memory launcher (copied to `dist`) |
| `package\README.txt` | End-user readme shipped in the zip |

## Rules for changes

- New resources (XAML, icons) must be **both** embedded in the exe (`/resource:` in `build.cmd`, named `MonitorControl.<file>`) **and** copied into `%OUT%\app\` for the launcher. Load them with `Program.OpenResource`.
- New framework references must be added both to `build.cmd` (`/r:`) and to `$refs` in the launcher.
- Input codes are MCCS defaults (HDMI 1 `0x11`, HDMI 2 `0x12`, DP `0x0F`, VGA `0x01`). Some monitors (including the AOC 27G2G3 this was built for) return an empty capabilities string, so don't rely on parsing capabilities.
- Switching input away from the PC's own connection blanks its screen. Keep the confirmation step in `RequestInput`.
- Don't try to work around Smart App Control by turning it off. That is irreversible without reinstalling Windows.
